# Launch Checklist

Use this checklist before submitting Maintainer Sentinel for open source support programs.

## Repository

- Public GitHub repository is available.
- README explains the maintainer problem, install path, usage, and read-only safety model.
- MIT license, contributing guide, security policy, issue templates, and CI are present.
- `v0.1.0` tag exists.

## Package

- `npm run lint` passes.
- `npm run typecheck` passes.
- `npm test` passes.
- `npm run build` passes.
- `npm pack --dry-run` contains only publishable package files.
- npm package is published when npm account access is ready.

## Adoption Signals

- Run reports against 5 public repositories and save useful learnings.
- Ask 3-5 maintainers for feedback.
- Track only real stars, forks, downloads, issues, and user feedback.
- Update the application draft before submission if any signal changes.

## Application

- Use the repository URL: `https://github.com/nikoaa666/maintainer-sentinel`.
- State the role as primary maintainer.
- Be explicit that the project is early-stage.
- Do not claim unearned adoption.
- Explain that API credits will power optional, reviewable maintainer assistance.
